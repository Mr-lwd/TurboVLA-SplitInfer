# 系统能力

从功能、性能和工程质量三个方面整理系统实现，并给出对应验证方式。

| 维度 | 实现机制 | 验证方式 / 关键指标 |
| --- | --- | --- |
| 功能性 | 本机基线、远程 sync / replace / blend、LIBERO 12×7 动作闭环 | 成功率、三模式原始记录、数值一致性 |
| 实时性 | 单请求后台推理、keep-alive、快速无损压缩、控制节拍 | 控制间隔 p95、往返、hold、过期块 |
| 实用性 | 双端职责明确、统一入口、YAML、preflight | 按部署步骤完成预检与单任务运行 |
| 稳定性 | 观测快照、动作对齐、过期裁剪、hold、异常传播 | 延迟注入、掉线、长时运行、hold 比例 |
| 安全性 | 报文限长、有界解压、形状/有限值校验、请求/实例匹配 | 非法载荷、服务重启、错误请求测试 |
| 一致性 | 无损压缩、严格权重加载、模型哈希、精度/块长检查 | codec 位保真、同一 checkpoint 的 parity 对比 |
| 可复现性 | seed、相同初始状态、模式顺序随机化、配置与环境元数据 | 原始记录、checkpoint SHA-256、设备环境 |
| 可观测性 | 调用/控制步 CSV、阶段计时、普通及墙钟视频 | metadata、summary、comparison |
| 可维护性 | 模型/协议/调度分层、六个测试模块、文档网站 | 单元回归、命令与链接核验 |
| 可扩展性 | 共用模型、独立 RoboTwin 训练评测入口、可选 codec | 新适配与独立测试 |

## 运行条件

split v1 使用 LIBERO 相对动作控制；控制频率配置为 20 Hz 上限，按实际时间戳统计运行节拍。请求超时或异常会结束当前实验并记录状态。依赖与模型资源见[设备部署](./deployment.md)，内存与计时口径见[验证与结果](./validation.md)。

当前客户端只支持 HTTP。服务适合受控实验网络，不应直接暴露到公网。若未来跨网络部署，应先增加 TLS、身份校验和访问控制，或使用明确配置的受保护隧道；现有 CLI 不能仅把 URL 改成 `https://` 就获得支持。

`request_id` 和 `server_id` 用于一致性匹配，不是鉴权。无损张量协议避免 pickle 网络反序列化，但模型文件仍应来自可信来源。

真机部署还需要独立于推理线程的失联看门狗、速度/工作空间限制、碰撞防护与急停；零增量 hold 不能替代这些措施。

## 验证顺序

按任务成功与动作一致性、延迟与缓冲状态、长时运行与资源监控的顺序验证。各阶段保存配置、设备环境和原始结果，便于复现与比较。
